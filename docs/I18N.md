# Idiomas (i18n)

O Minha Fila fala **português (pt_BR)**, **inglês (en)** e **espanhol (es)**. O padrão é `pt_BR`. O mesmo locale vale no painel Next.js, nas mensagens da API Laravel e nos e-mails (Magic Link).

## Ordem de detecção (backend)

Middleware `App\Http\Middleware\SetLocale` (API + web):

1. **Usuário autenticado** — `users.locale` (Sanctum resolvido cedo no middleware).
2. **Header/param do frontend** — `X-Locale`, `?lang=` / `?locale=`, body `locale`/`lang`.
3. **Accept-Language** do navegador.
4. **Fallback** — `pt_BR` (`config/app.php`).

Códigos persistidos no banco/API: `pt_BR`, `en`, `es`. No browser/`Intl`/HTML `lang` usa-se BCP 47 (`pt-BR`, `en`, `es`).

## Frontend

Camada leve em `frontend/src/lib/i18n/` (dicionários + `I18nProvider` / `useI18n`), sem lib pesada.

| Superfície | Fonte do idioma |
|---|---|
| Login / painel / billing | `users.locale` (após login) ou escolha local + `localStorage` / cookie `preferred_locale` |
| Fila pública `/filas/[uuid]` | Só o aparelho do cliente (`I18nProvider deviceOnly` + `navigator.language`) — **não** herda o locale do dono |

Seletor de idioma: login (`LocaleSelector` local) e menu do painel (`AdminUserMenu` → `PATCH /api/user/locale`).

Todas as chamadas Axios enviam `X-Locale` e `Accept-Language`. Datas/horas usam `Intl` com o locale ativo (`lib/datetime.ts`).

## E-mails

`MagicLinkMail` usa `__('mail.magic_link.*')` com `Mail::to(...)->locale($locale)`.

- Conta existente: `users.locale`.
- Primeiro acesso: idioma do pedido (header/param/`Accept-Language`).

## Como adicionar um idioma

1. Incluir o código em `App\Support\Locale::SUPPORTED` e `frontend/src/lib/i18n/locales.ts` (`APP_LOCALES` + labels).
2. Backend: criar `lang/{locale}/` (`validation.php` só com as regras usadas pelo app, `auth.php`, `passwords.php`, `mail.php`, `api.php`) e `lang/{locale}.json` para mensagens flat da API.
3. Frontend: preencher o dicionário em `frontend/src/lib/i18n/dictionaries.ts`.
4. Migration não é necessária se o código couber em `string(8)`; valide no `UserSettingsController`.

## Como adicionar uma string

1. **UI:** chave em `dictionaries.ts` nos três idiomas; usar `t('chave')` / `t('chave', { param })`.
2. **API/e-mail:** chave em `lang/{locale}/api.php` ou `mail.php` e `__('api...')` / `__('mail...')`.
3. Manter o texto **pt_BR** idêntico ao comportamento atual (sem regressão de copy).

## Endpoint

`PATCH /api/user/locale` — body `{ "locale": "pt_BR"|"en"|"es" }` (auth Sanctum). Resposta `{ "locale": "..." }`.

Payloads de login (magic link / Google) incluem `user.locale`.
